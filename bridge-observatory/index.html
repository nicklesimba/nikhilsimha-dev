Load Posting Compliance Observatory

A camera-only screening instrument: does traffic obey this bridge's posted weight limit, and can the owner prove what was seen?

What this is, in one paragraph

This tool watches traffic crossing a load-posted bridge and asks one question per vehicle: can we prove this crossing broke the posted weight limit? It flags a crossing only when the documented minimum weight of that vehicle's class, the lightest that class can possibly be when completely empty, already exceeds the tonnage on the sign. If that test does not settle it, the answer is undecided, and the crossing is written to an audit ledger with the reason it could not be decided. It is built for the owner of a small posted bridge, a county or town engineer who has a sign and no way of knowing whether anyone obeys it.

Expect this

Most crossings end in "undecided", and that is the output, not a failure. On the footage shipped here, effectively every crossing is undecidable, because the bridges are either not load posted at all or the detector's label is too broad to pin a minimum weight to. The page shows you why, crossing by crossing. A tool of this kind that reported confident violations on this footage would be lying.

About this page

These are recorded runs. Every frame, verdict and number below came out of the real pipeline on a real clip, rendered ahead of time so the tool can be shown without a server. The app itself runs locally on Python, PyTorch and OpenCV, which GitHub Pages cannot host. Source is closed; this page is the demo.

Reading the overlay: what each number on the picture means

Important: the colours and percentages come from an illustrative model of class-typical weights. They are an illustration of load on the structure and they play no part in any compliance verdict. The verdicts use documented minimum weights and the posted limit, and nothing else.

The box tint

A label like CAR #14 means: a car, tracked as vehicle 14. The tint shades the class by how heavy that class tends to be on this structure. It carries no number, because a percentage of capacity would be an assumed weight, and this version acts only on weights it can defend.

The #14 after the class

A tracking id, so one vehicle crossing becomes one crossing event instead of three hundred boxes. It is how crossings get counted. It is not a plate: this tool does no plate recognition.

The audit record

Every vehicle that crossed is one row, whether it could be judged or not. Nothing is summarised away: each rate below is printed next to the exact number it was divided by, and the count of crossings the tool declined to decide is displayed as prominently as the flags, because a compliance figure without its undecided count would be misleading.

The posted limit, and where the number came from

This tonnage is the only thing a verdict is decided against, so its provenance sets the ceiling on what any result here is worth. The federal inventory records that a bridge is posted but never what the sign says, which is why the value has to be sourced separately.

Structure context (NBI record)

Background on the bridge from the federal National Bridge Inventory. None of it decides a verdict: only the posted limit does.

Condition codes run 0 to 9, where 9 is excellent, 5 is fair and 4 or below is poor. The load rating is an engineer's calculated capacity, not the tonnage on the sign. NBI posting code 5 means the state evaluates the bridge as carrying legal loads; lower means posted below them.

Why it could not decide

Crossings by vehicle class (this session)

Class comes from the detector's most frequent label over the whole track. A COCO "truck" spans a pickup through a semi, which is exactly why a class whose documented minimum weight does not clear the posted limit abstains instead of guessing. The "within limit" count is always zero by design: see the glossary below.

Glossary for the words on this page

Crossing
One tracked vehicle passing through the frame, from first sight to last. Not one box per frame: three hundred boxes of one truck are one crossing.
Flagged, or certificate-grade exceedance
A crossing where the vehicle class's documented minimum weight when completely empty already exceeds the posted limit. It is a conservative certificate, not an estimate of what the vehicle weighed.
Undecided, or abstention
A crossing the tool refused to judge, stored as a full row with the reason. It is a result, not a dropped record.
Within limit
A verdict this tool never issues. Calling a vehicle legal would need a documented class maximum, and a manufacturer's weight rating says nothing about the mass of a vehicle on the day, while an overloaded vehicle is precisely the population a posting cares about. The column exists because the ledger has three verdict slots; it stays at zero on purpose.
Flag rate
Flagged crossings divided by decided crossings. When nothing was decidable the denominator is zero, and the page says so instead of printing a reassuring 0%.
Session
One press of Analyze on one clip.

Read this before quoting any number above

  • Informational screening only, NOT an engineering assessment. Consult NBI/DOT postings and a licensed engineer.
  • Screening, not enforcement. This is not a citation system and it does not measure weight. A verdict says a vehicle class cannot weigh less than the posted limit, never what this vehicle weighed.
  • Every crossing is recorded, including abstentions. An abstention count is part of the result, not a footnote: rates here are always shown with the denominator they were divided by.
  • There is no verdict meaning "within the limit". Calling a vehicle legal would need a documented class maximum, and a manufacturer's weight rating says nothing about the mass of a vehicle on the day. So zero exceedances never means the traffic complied, only that nothing met the bar for saying otherwise.
